## Contract (docs/design/build-contract.md)

- Specification: build contract section 8.1 and build contract section 8.4 and build contract section 8.6 (providers, requests, error translation); docs/design/provider.md section 3 and docs/design/provider.md section 9 (endpoints, live and recording providers).
- LiveTransport(http_client, settings, credentials=None, api_key=None, quota_recorder=None, sleep=time.sleep, rng=None) implements ApiTransport with the paths and authorisation rules of docs/design/provider.md section 3 and the retry policy of docs/design/provider.md section 9; status 400 or more raises ApiHttpError(status, body); a successful call reports (endpoint, units) to quota_recorder with units from quota.costs. LiveYouTubeProvider(ApiBackedProvider) and RecordingProvider (ApiBackedProvider over RecordingTransport) take their transport as an argument. The server connects quota_recorder to QuotaGuard.record with the current request id from ytmcp.logging_setup.
- .github/workflows/live-smoke.yml (cron weekly and workflow_dispatch, never on pull_request): uses only the secret YT_API_KEY, runs python -m pytest -m live -q and then python scripts/check_quota_budget.py with --max 500. The release workflow belongs to the release task S4-7, not to this item.

## Layer rules (docs/design/build-contract.md section 2)

- providers/live.py is the only module in src that imports httpx.
- live.py and recording.py may import infra (quota recorder protocol, clock) but never services.
- Sleep and RNG are injected so that retry tests need no real waiting.

## Acceptance tests (write first)

- tests/integration/test_live_provider_mocked.py with httpx.MockTransport: the path and query of every method; API key for public reads, bearer token for mine, myRating and writes; POST bodies for the two inserts; retries (3 times on 5xx and on timeouts, with the delays of docs/design/provider.md section 9 recorded by the injected sleep; Retry-After honoured and capped at 30; no retry on 400, 401, 403 and 404); after the last retry 429 gives RATE_LIMITED and 5xx gives UPSTREAM_ERROR; quota recorded once per successful call with the right units.
- Shared contract tests run the read-method checks on FixtureYouTubeProvider and on LiveYouTubeProvider over a MockTransport that serves the fixture files and get equal results.
- tests/negative/test_api_errors.py: each error fixture (quotaExceeded, youtubeSignupRequired, authError, rateLimitExceeded, backendError) gives the right YtmcpError through the live provider.
- tests/live/test_live_smoke.py (marker live): skipped unless YT_API_KEY is set; at most two search calls and a few reads; it prints the units used.
