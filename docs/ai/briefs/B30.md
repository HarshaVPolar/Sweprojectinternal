## Contract (docs/design/build-contract.md)

- Specification: build contract section 9 (get_quota_status, get_auth_status, resources); docs/api/tools.md section 3.8, docs/api/tools.md section 3.9 and docs/api/tools.md section 4; build contract section 3 (limits.rate_limit_per_min); SRS QTA-6, UI-5, SEC-11.
- get_quota_status now reads QuotaGuard.status(); get_auth_status reads OAuthManager.auth_status() and, only when a token exists, calls my_channel() for channel_present. Resources: youtube://quota/status, youtube://video/{id} (reads only the cache; an uncached video returns a plain message and makes no API call), youtube://playlist/proposal/{id} (state, expiry, items; never approval data) and youtube://auth/status, all returning JSON with untrusted text delimited.
- Rate limiting: build_server wraps every tool so that RateLimiter.acquire("default") runs before the handler; a rejection is returned as the error envelope with RATE_LIMITED. Every tool result reports quota.spent (QuotaLedger.spent_for the request id) and quota.remaining (UI-5); a tools-level helper builds the quota report so that no tool computes it by hand.

## Layer rules (docs/design/build-contract.md section 2)

- tools and resources import services, models, errors and ytmcp.tools; the sanitiser exception of the brief of B24 applies.
- server.py wires the real guard, the OAuth manager and the rate limiter through Runtime.

## Acceptance tests (write first)

- tests/system/test_status_tools.py: the four resources are listed and readable; get_quota_status returns the real numbers after a recorded call; get_auth_status with a fake OAuth manager reports has_token and scopes and never a token value (plant a recognisable token string and assert it appears nowhere in any tool or resource output); the proposal resource never contains approval data.
- tests/system/test_rate_limit_mcp.py: start the server with YTMCP_LIMITS__RATE_LIMIT_PER_MIN set to 3; the fourth call within a minute returns RATE_LIMITED.

## Forbidden

New dependencies, HTTP outside providers/live.py, reading .env or token files, weakening tests, changing files outside the list, inventing API fields that are not present in tests/fixtures.

## Output

Small, focused change, traceability row.
