## Contract (docs/design/build-contract.md)

- Specification: build contract section 7.2 (cache row); build contract section 5 (video_cache, channel_cache, kv_cache); build contract section 3 (cache.* keys); docs/adr/002-sqlite-storage.md.
- API (added): Cache(conn, clock, settings: CacheConfig); get(key, kind) -> dict or None; put(key, kind, value) -> None; stats() -> CacheStats(hits, misses); purge(kind=None) -> int; purge_expired() -> int. Kinds: video and channel (tables video_cache and channel_cache, TTL cache.ttl_video_channel_h hours), search (kv_cache key prefixed search:, TTL cache.ttl_search_h hours) and categories (kv_cache key prefixed categories:, TTL cache.ttl_categories_d days). An unknown kind raises ValueError; a value that is not JSON-serialisable raises TypeError.
- A record is fresh while now is before fetched_at plus ttl and expired from that instant on; an expired row is treated as absent. A cache hit costs 0 units: the calling service records it as a hit in its quota report.

## Layer rules (docs/design/build-contract.md section 2)

- cache.py imports sqlite3, models, errors, config and ytmcp.infra.clock only.

## Acceptance tests (write first)

- tests/unit/test_cache.py with FakeClock and a temporary database: put and get round trip for each kind; the exact expiry boundaries for 24 hours, 24 hours and 7 days; the same key in different kinds does not collide; overwriting refreshes fetched_at; stats count hits and misses; purge removes only the given kind; purge_expired removes only expired rows; an unknown kind raises ValueError; a non-serialisable value raises TypeError.
