## Contract (docs/design/build-contract.md)

- Specification: build contract section 10 (state machine and approval gate); build contract section 7.3 (ConfirmationGate row); docs/adr/004-human-approval-gate.md; docs/design/security.md section 2 and docs/design/security.md section 3 (threats T-01, T-03 to T-06); docs/design/elicitation-spike.md (result of ES-1).
- ConfirmationGate(conn, clock, secret, mode, audit, server_factory). The per-install secret is 32 random bytes in data_dir/gate.key (mode 0600 on POSIX), created on first use by load_or_create_secret(path). ApprovalContext is a typing Protocol with supports_elicitation() -> bool and an async elicit(message) -> ElicitAnswer (accept, decline or cancel); the tool adapts the installed MCP SDK context to it, so the gate depends only on the protocol. async request_approval(proposal, ctx) -> "granted", "denied" or "pending" in the modes elicitation, oob and auto of build contract section 10; verify_and_consume(proposal_id) -> None raises ProposalInvalid on any failed check. Approval values and nonces are stored only as HMAC-SHA256 of proposal_id, items_hash and the random value. build_summary(proposal) -> str builds the text shown to the human (title, number of videos, total duration, visibility, shortfall, cost).
- infra/approval_server.py: a loopback HTTP server on 127.0.0.1 with a random port and a random 128-bit path nonce; a page showing the summary with Approve and Decline buttons and a per-page CSRF value; Host and Origin checks; one decision only; decisions are passed to the gate through an injected callback, so infra never imports services. The URL is printed to stderr and never returned in a tool output.

## Layer rules (docs/design/build-contract.md section 2)

- services/confirmation_gate.py is the only place that sets approval_state to granted.
- infra/approval_server.py imports only the standard library, models, errors and config.
- The gate imports infra (db, clock, audit log, approval server) and models and errors.

## Acceptance tests (write first)

- tests/unit/test_gate.py and tests/security/test_gate_bypass.py with FakeClock, a temporary database and a fake ApprovalContext: elicitation accept, decline and cancel; mode auto chooses elicitation only when supported; oob returns pending, then granted after a valid POST; the stored approval is an HMAC value, never plain; single use (second verify fails); expiry after 15 minutes; an altered items hash fails; a state other than PROPOSED (or PARTIALLY_CREATED on resume) fails; a POST without the CSRF value gets 403; a wrong Host or Origin is refused; a wrong path nonce gets 404; a second decision is refused; the server is bound to 127.0.0.1 only; a source-grep test shows that only confirmation_gate.py writes approval_state.
- The request_approval result and every exception text contain neither the nonce nor the URL.
