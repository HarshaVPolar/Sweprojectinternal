## Contract (docs/design/build-contract.md)

- Specification: build contract section 3 (limits.rate_limit_per_min); build contract section 7.2 (rate_limiter.py row); docs/design/security.md (threat T-09).
- RateLimiter(clock, per_minute) with acquire(client_id="default") -> None. A token bucket per client: capacity per_minute, refill per_minute / 60 tokens per second; acquire takes one token or raises RateLimited, whose message says how many seconds to wait. per_minute below 1 raises ValueError. The bucket map is guarded by a threading.Lock.

## Layer rules (docs/design/build-contract.md section 2)

- infra: imports errors and ytmcp.infra.clock only.

## Acceptance tests (write first)

- tests/unit/test_rate_limiter.py with FakeClock: 30 acquires at the same instant pass and the 31st raises RateLimited; after 2 seconds one more token is available; after 60 seconds the bucket is full again but never exceeds 30; two clients are independent; per_minute 0 raises ValueError; five threads acquiring concurrently never exceed the capacity.
- tests/negative/test_rate_limit.py: the error has code RATE_LIMITED and retryable true.
