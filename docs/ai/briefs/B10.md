Size: L
Stage: S3

## Contract (docs/design/build-contract.md)

- Specification: build contract section 13 (validation rules); build contract section 9 (untrusted-text rule and delimiters); build contract section 7.1 (input_validator.py and sanitiser.py rows); docs/design/security.md (threats T-01 and T-02).
- normalise_video_id(raw) -> str: accepts an 11-character ID or a URL of the forms watch?v=, youtu.be/, shorts/ and embed/ on the allowed hosts; a value without a scheme and not an 11-character ID is parsed as https:// plus the value; any whitespace, userinfo, port, scheme other than http or https, other host, non-string or length above 2048 raises InvalidId; the extracted ID must match ^[A-Za-z0-9_-]{11}$.
- normalise_channel_ref(raw) -> ChannelRef: a UC identifier gives kind id; @handle (3 to 30 characters of letters, digits, dot, underscore, hyphen) gives kind handle with the @ kept; URLs give /channel/UC... kind id, /@handle kind handle, /user/name kind username and /c/name kind custom (name 1 to 100 characters of letters, digits, dot, underscore, hyphen); extra path segments after the identifier are ignored; hosts youtube.com, www.youtube.com and m.youtube.com only.
- validate_playlist_request(raw) -> PlaylistRequest: accepts the tool keys topic, total_duration, max_video_duration, language, title, visibility and tolerance_pct, maps the two duration keys to total_duration_s and max_video_duration_s, requires integers (not booleans, not strings), rejects unknown keys and control characters in topic and title, and converts a validation failure into InvalidParameter whose message names the first failing field.
- sanitise_text(s, max_len=500) -> str: NFKC normalise; remove control characters and Unicode format characters (zero-width characters, bidi controls, byte-order mark, tag characters); remove HTML and XML tags repeatedly until none is left; remove the delimiter tokens [[UNTRUSTED_YOUTUBE_TEXT]] and [[/UNTRUSTED_YOUTUBE_TEXT]] case-insensitively; collapse whitespace to single spaces and strip; truncate to max_len characters, ending with three dots when truncated and max_len is at least 4; a non-string raises TypeError. wrap_untrusted(s) returns the opening delimiter line, the text and the closing delimiter line, after removing any delimiter tokens from the text.

## Layer rules (docs/design/build-contract.md section 2)

- domain imports only models, errors and the standard library (re, unicodedata, urllib.parse); pure functions; mypy strict.
- Only tools and resources call the sanitiser; services keep raw text.

## Acceptance tests (write first)

- tests/unit/test_validator.py: every URL form for videos and channels; malformed IDs (abc, SQL fragments, 5000 characters, wrong host, youtube.com.evil.com, userinfo, a port, spaces); each ChannelRef kind; validate_playlist_request edges, key mapping, unknown keys and wrong types.
- tests/security/test_injection_corpus.py with at least 21 inline payloads in these families: 4 instruction override, 3 fake tool-call syntax (JSON that names confirm_playlist), 3 markup (script tag, markdown image link, HTML comment), 4 forged delimiters (exact, lower case, full-width brackets, zero-width characters inside), 3 hidden Unicode (zero-width space, right-to-left override, tag characters), 2 role impersonation (SYSTEM: and Assistant: lines), 2 encoded text (base64 and hex). For each payload the sanitised text has no control or format characters, no tags, no delimiter token, is within max_len, and after wrap_untrusted the result contains exactly one opening and one closing delimiter line. The words of an instruction may remain, but only inside the delimiters.
- tests/security/test_input_fuzz.py (hypothesis): the normalisers either return a value that matches the grammar or raise InvalidId, never another exception; sanitise_text never raises for any string and its output never contains control characters.
