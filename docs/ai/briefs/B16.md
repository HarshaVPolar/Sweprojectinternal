## Contract (docs/design/build-contract.md)

- Specification: build contract section 12 (quota rules); build contract section 3 (quota.*); build contract section 5 (quota_ledger, request_log); build contract section 7.3 (QuotaGuard); docs/adr/002-sqlite-storage.md.
- QuotaLedger(conn, clock): record(request_id, endpoint, units) inserts a row with the Pacific-time day; used_today() -> int; spent_for(request_id) -> int; mark_exhausted() inserts one ledger row for today with the endpoint "__exhausted__" and 0 units (added, no schema change); is_exhausted() -> bool; log_request(request_id, tool_name, est_units, actual_units, outcome) writes request_log.
- QuotaGuard(settings: QuotaConfig, ledger, clock): check(plan, request_id) -> Estimate; record(endpoint, units, request_id); status() -> QuotaStatus; mark_exhausted(). Integer arithmetic: reserve = daily_budget x safety_reserve_pct // 100; usable = daily_budget - reserve; global_remaining = usable - used_today; machine_remaining = machine_daily_budget - used_today; limit = min of the two. check raises QuotaBudgetExceeded (message with the estimate and the remaining units) when estimate is above max(limit, 0); an estimate of 0 always passes; an exhausted day with an estimate above 0 raises QuotaExhausted with the reset time. check never writes to the ledger. status().reset_at is clock.next_reset().

## Layer rules (docs/design/build-contract.md section 2)

- QuotaLedger is in infra (imports models, errors, config and ytmcp.infra.clock); QuotaGuard is in services (imports infra, models, errors, config).
- Services build a plan that leaves out cached items, call check, execute, then record.

## Acceptance tests (write first)

- tests/unit/test_quota_guard.py with FakeClock and a temporary database: an estimate exactly at the limit passes and one unit more is rejected; the 5 percent reserve gives 9500 usable units; a smaller machine budget dominates; used units persist across new ledger and guard objects on the same file; a new Pacific day resets used_today; the exhausted marker persists, blocks estimates above 0 and clears on the next day; check leaves the ledger unchanged; a plan with count 0 gives estimate 0; spent_for sums one request; status fields.
- tests/system/test_quota_reject.py: a small workflow runner defined in the test calls guard.check before a counting fake provider; a rejected workflow makes zero provider calls.
