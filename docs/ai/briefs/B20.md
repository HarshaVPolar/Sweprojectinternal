## Contract (docs/design/build-contract.md)

- Specification: build contract section 7.2 (oauth.py row); build contract section 3 (no secrets in configuration); docs/adr/005-oauth-and-token-storage.md; docs/design/security.md (threat T-08); docs/adr/001-runtime-and-dependencies.md.
- OAuthManager(store: TokenStore, clock, client_id, client_secret, authoriser=None, refresher=None, warn_days=6). credentials(scopes) -> Credentials (a frozen dataclass with access_token with repr=False, expires_at, scopes). Read workflows request only https://www.googleapis.com/auth/youtube.readonly; the scope https://www.googleapis.com/auth/youtube is requested only when a write is about to happen. When the stored token lacks a requested scope, run the consent flow again with the union of old and new scopes (incremental authorisation).
- Default authoriser: google_auth_oauthlib InstalledAppFlow with PKCE (code verifier and S256 challenge), a state value that the library checks, access_type offline, prompt consent and run_local_server on a random free port, opening the system browser and printing the URL and the requested scopes to stderr. Default refresher: google.oauth2.credentials.Credentials.refresh with google.auth.transport.requests.Request. Both are injectable so that tests never touch the network.
- Rules: one refresh attempt on a 401 or invalid_grant, then raise ReauthRequired and start a new consent flow on the next authorised call; with no stored token raise AuthRequired unless an interactive consent is allowed; auth_status() -> AuthStatus(has_token, scopes, expires_at) never returns token values; expiry_warning() returns a message when the token is at least warn_days old (day 6 of the 7-day Testing-mode limit) and None otherwise. The client id and secret come from the environment variables YT_CLIENT_ID and YT_CLIENT_SECRET, read by the server, never stored in Settings.

## Layer rules (docs/design/build-contract.md section 2)

- infra: only this module imports google_auth_oauthlib and google.auth (the HTTP rule of build contract section 2 allows it to talk to the Google OAuth endpoints).
- It uses TokenStore for storage and never reads token files itself.

## Acceptance tests (write first)

- tests/integration/test_oauth.py with fake authoriser and refresher: the exact scope strings for a read call and for a write call; the union on an incremental upgrade; a valid token needs no consent; an expired access token is refreshed once and then reused; the default authoriser is built with PKCE and offline access (inspect the flow arguments through a patched factory, never run the flow); the day-6 warning at 6 days and none at 5 days; auth_status has no secrets.
- tests/negative/test_expired_token.py: invalid_grant on refresh raises ReauthRequired exactly once (one attempt), the stored token is removed, and the next call starts a new consent; a missing token raises AuthRequired.
