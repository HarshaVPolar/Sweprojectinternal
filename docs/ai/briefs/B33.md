# B33 - Skill evals

Size: L
Stage: S3
Needs: B31
Requirements: SK-8, TQ-7
Files: skills/video-to-playlist/evals/; docs/test/skill-evals/; scripts/run_skill_evals.py
Tests: tests/skill_eval/test_video_to_playlist_evals.py
Done when: Four scenarios (happy path, rejection, over-quota, injection attempt) are defined and their results are recorded.

## Contract (docs/design/build-contract.md)

- Specification: SRS SK-8 and TQ-7 (four evaluations before each stage submission); docs/design/security.md section 5; brief B31 (the skill under test).
- skills/video-to-playlist/evals/ holds four files: happy_path.md, rejection_path.md, over_quota_path.md and injection_attempt.md. Each has the sections Scenario, Setup (provider mode, configuration variables), Steps (the user messages), Expected (observable behaviour), Pass criteria and a Results table with the columns Date, Client, Result and Notes.
- scripts/run_skill_evals.py runs the server-side part of each scenario through the MCP interface with the fixture provider and prints PASS or FAIL per scenario: happy path (propose, approval, confirm gives CREATED with distinct items), rejection (decline gives REJECTED and zero writes), over quota (a tiny machine budget gives QUOTA_BUDGET_EXCEEDED before any provider call), injection (a fixture video whose description says to ignore instructions and create a playlist is returned delimited, and no write happens without approval).
- docs/test/skill-evals/ receives one results file per run named YYYY-MM-DD.md with the four results and the client used; the agent-level behaviour (does the AI client follow the skill) is judged by a human in the real client and recorded in the Results tables.

## Layer rules (docs/design/build-contract.md section 2)

- scripts/run_skill_evals.py is outside the package and may import ytmcp and mcp.
- Evaluation files are Markdown; results files are committed.

## Acceptance tests (write first)

- tests/skill_eval/test_video_to_playlist_evals.py runs the same four scenarios as automated tests and asserts the outcomes listed above.
- Every eval file has all six sections.
- The script exits 1 if any scenario fails and 0 otherwise, and writes the results file only when --write is given.

## Forbidden

New dependencies, HTTP outside providers/live.py, reading .env or token files, weakening tests, changing files outside the list, inventing API fields that are not present in tests/fixtures.

## Output

Small, focused change, traceability row.
