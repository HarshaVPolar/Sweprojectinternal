# B01 - Config loader

Size: M
Stage: S2
Needs: none
Requirements: NFR-MNT-3
Files: src/ytmcp/config.py
Tests: tests/unit/test_config.py
Done when: Loads every key of config/default.toml with environment overrides named YTMCP_<SECTION>__<KEY> into an immutable typed Settings object; a wrong type or an unknown key fails fast.

## Contract (docs/design/build-contract.md)

- Specification: build contract section 3 (keys, types, constraints, environment rules) and build contract section 1 (conventions).
- Built in Stage 2 in src/ytmcp/config.py: Settings and its section models, ConfigError, DEFAULT_CONFIG_PATH and load_settings(path=None, env=None).
- Secrets are never stored in Settings; YTMCP_TOKEN_PASSPHRASE is never read by the configuration.

## Layer rules (docs/design/build-contract.md section 2)

- config.py imports nothing from ytmcp; only pydantic and the standard library.
- Services receive the Settings sections they need through their constructors; domain code never imports config.

## Acceptance tests (write first)

- Built in Stage 2; tests/unit/test_config.py covers default values, frozen settings, valid and invalid environment overrides, ignored variables, provider and data_dir, file variants (unknown key, weight sums, bad time zone, missing section, invalid TOML, missing file), the os.environ default and ConfigError being a ValueError.
- A change of config/default.toml needs a matching change of build contract section 3 and of config.py in the same commit.

## Forbidden

New dependencies, HTTP outside providers/live.py, reading .env or token files, weakening tests, changing files outside the list, inventing API fields that are not present in tests/fixtures.

## Output

Small, focused change, traceability row.
