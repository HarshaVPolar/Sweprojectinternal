## Contract (docs/design/build-contract.md)

- Specification: build contract section 9 (analyse_engagement); docs/api/tools.md section 3.4; SRS FR-4.1 to FR-4.7.
- domain/stats.py (added): a frozen dataclass EngagementItem(source, channel_id, channel_title, category_id, duration_s, at, at_kind) with source in like, playlist, subscription. top_channels(items, k) counts likes and playlist items per channel and marks subscribed channels, sorted by count descending, then title, then ID. category_distribution(items, names) gives entries with category_id, name ("Unknown" when missing), count and percent rounded to one decimal. trend(items, granularity) counts per month (YYYY-MM) or ISO week in UTC, sorted ascending, with empty buckets filled between the first and the last. duration_stats(durations_s) gives count, mean, median, q1, q3 (statistics.quantiles, n=4, method inclusive) and the buckets under 5, 5-10, 10-20, 20-40 and 40 or more minutes (lower bound inclusive: 299 s is under 5, 300 s is 5-10, 2400 s is 40 or more); empty input gives zeros. compare_periods(cur, prev) gives for each metric current, previous, abs_change and rel_change (None when previous is 0).
- EngagementService.analyse(period, compare_to, dimensions, top_k, granularity): reads the user data through the guard, uses video_categories for names (cache 7 days), cuts the periods from the clock (the previous period is the same length just before the current one; "all" has no previous period and adds a notice), and states timestamp_used: likes use the video publication time, playlist items the time added, subscriptions the subscription time. Every report contains the limitations text "Data limits: YouTube does not provide watch history, and liked videos have no like timestamps, so trends for likes use the video publication date." An empty period returns zeros and the notice "No activity in this period." All analysis is local (FR-4.7).
