## Contract (docs/design/build-contract.md)

- Specification: build contract section 5 (schema and pragmas); docs/design/schema.md; docs/adr/002-sqlite-storage.md.
- Create migrations/001_init.sql containing exactly the SQL block of build contract section 5.
- API (added): connect(path) -> sqlite3.Connection creates the parent directory, applies the four pragmas, sets row_factory to sqlite3.Row and isolation_level to None; migrate(conn) applies migrations/NNN_*.sql in numeric order, one transaction each, and keeps the single schema_version row equal to the highest applied number (insert the first time, update afterwards); transaction(conn) is a context manager running BEGIN IMMEDIATE and then COMMIT, or ROLLBACK on an exception; MIGRATIONS_DIR is the repository root plus migrations. A gap in the migration numbers raises ValueError. On POSIX the database file gets mode 0600.

## Layer rules (docs/design/build-contract.md section 2)

- db.py uses only the standard library (sqlite3, pathlib, contextlib).
- Only infra and services use the connection; domain and tools never do.

## Acceptance tests (write first)

- migrate creates the ten tables and sets version 1; running it twice is harmless; a gap in migration numbers (use a temporary migrations directory) raises ValueError.
- transaction commits, and rolls back on an exception; uncommitted work is gone after the connection closes.

- The parent directory is created; the POSIX mode is 0600 (skip on Windows).
- The text of migrations/001_init.sql equals the SQL block of build contract section 5 after whitespace normalisation.
