## Contract (docs/design/build-contract.md)

- Specification: build contract section 10 (state machine and approval gate); build contract section 9 (confirm_playlist); docs/api/tools.md section 3.6; docs/design/security.md section 3 (flows); docs/adr/004-human-approval-gate.md.
- PlaylistService.confirm(proposal_id) is async (MCP elicitation is async) and awaits the gate; blocking provider calls run in a worker thread. Steps: load the proposal; check state, expiry and the recomputed items hash; request approval (pending raises ApprovalPending; denied sets REJECTED and raises ProposalInvalid with a message saying it was declined); verify_and_consume and write the audit entry confirm; check the guard for channels_list 1 + playlists_insert 1 + playlist_items_insert for each missing item; set CONFIRMED; my_channel() None sets FAILED and raises ChannelRequired; create the playlist (title is the request title or the topic followed by " (curated)", at most 150 characters; the requested visibility) and store its ID; add the items in order, setting added_ok after each success; all added gives CREATED and the audit entry create; a failure after the playlist exists gives PARTIALLY_CREATED (QuotaExhausted also calls guard.mark_exhausted); a failure before gives FAILED. Resume (state PARTIALLY_CREATED): list the playlist items (1 unit), mark the items already present, ask for a new approval, add only the missing items, never duplicates. The tool returns playlist_url https://www.youtube.com/playlist?list=<id>. server.py wires the gate, the approval mode from settings.approval.mode and the confirm tool; the tool adapts the SDK context to ApprovalContext.
